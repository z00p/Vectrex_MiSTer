# um2run (alpha)

Runs an unmodified **UVMC2 cartridge image** (`.um2`, an RP2350 firmware image) on the MiSTer's
ARM processor, with the Vectrex-PiTrex core as the console. It emulates the cartridge's bus
hardware (PIO, DMA, SIO, SD card, timers, cart audio) and turns what the image does to the
Vectrex bus into the same command stream the PiTrex programs use. See [DESIGN.md](DESIGN.md).

Unofficial and experimental. It is not part of the UVMC2 project: please do not report MiSTer
problems to the UVMC2 team. **No cartridge images, ROM sets or card images are included**: bring
your own. User guide: [../UVMC2_GAMES.md](../UVMC2_GAMES.md).

Normally you don't run it by hand: pick the game in the core's OSD (**Load UVMC2 / PiTrex**) and
`pitrexd` starts it with the settings from the game's sidecar file.

## Files
| File | |
|---|---|
| `um2run.c`, `um2bus.c/.h`, `um2sd.c/.h`, `um2aud.c/.h` | the program (loader, device model, SD card, cart audio) |
| `um2bus_replay.c` | host tool: replays a capture (`--capture FILE`) through the device model |
| `build.sh` | static ARM (Cortex-A9) build, plus the host replay tool |
| `mister_run.sh` | starts it on the MiSTer with the proven CPU placement and priority |
| `selftest/` | synthetic guests (generated by the Python scripts) and `selftest.sh`: no images needed |
| `DESIGN.md` | how it works |

It uses the PiTrex stream layer in `../src` (`ptx_core.c`, `ptx_backend_*.c`).

## Build
On a PC with the ARM cross compiler (Debian/Ubuntu or WSL: `apt install gcc-arm-linux-gnueabihf`):
```
cd pitrex/um2run
./build.sh            # produces ./um2run (static, ARM) and the host tool ./um2bus_replay
```
The binary is not kept in git. Copy `um2run` and `mister_run.sh` to `/media/fat/pitrex/um2run/` on
the MiSTer (the release zip and PiTrex_Setup do this for you).

Self test (needs `qemu-user`, `apt install qemu-user`): `./selftest/selftest.sh` should print eight
`PASS` lines.

## Run by hand (SSH on the MiSTer)
The Vectrex-PiTrex core must be loaded with PiTrex Mode on (the **UVMC2 Games** entry in the
PiTrex & UVMC2 menu does that), and both CPUs must be online (`cat /sys/devices/system/cpu/online`
says `0-1`; after BigMig a normal reboot is needed).
```
cd /media/fat/pitrex/um2run
./mister_run.sh /media/fat/games/Vectrex-PiTrex/UVMC2/Game.um2 --sd /path/to/card.img --secs 1000000000
./mister_run.sh --stop
```
The log is `/tmp/um2.log`. Useful `um2run` options:

| Option | |
|---|---|
| `--sd IMAGE` | SD card image the cartridge sees (read/write if the file is writable) |
| `--frame-cycles N` | stream frame length in E cycles (default 30000 = 50 Hz; 25000 = 60 Hz) |
| `--secs S` | stop after S seconds (`--bus` stops after 300 s by default) |
| `--no-loading` | no LOADING screen while the image has not drawn its first frame |
| `--no-hold` (mister_run.sh) | do not hand each frame to the ring at once (`--hold` is the default) |
| `--bus-verbose`, `--ringmon` | model log and a once-a-second ring monitor, for diagnosis |

## Sidecar file
`pitrexd` reads `<image>.um2.cfg` next to the picked file: `key=value` lines, `#` comments,
nothing is executed. Keys: `frame_cycles`, `sd`, `args`, `settle`, `cpu1_after`, and the
experimental `orient` and `view`. They are described in [../UVMC2_GAMES.md](../UVMC2_GAMES.md).

## Environment switches that matter to users
| Variable | |
|---|---|
| `PTX_WAIT_CORE=60` | set by `mister_run.sh`: wait up to 60 s for the Vectrex-PiTrex core |
| `UM2_NOAUDIO=1` | no cart audio (the games' sound then comes from the Vectrex PSG where they use it) |
| `UM2_AUDPRE=<ms>` | cart audio jitter buffer, default 60, at most about 90 |
| `SETTLE=<s>`, `CPU1_AFTER=<s>` | `mister_run.sh`: black-screen guard timings (sidecar keys `settle`, `cpu1_after`) |
| `UM2_NOVFP=1`, `UM2_NOSPIPATCH=1` | switch off an optimisation, to find out whether it is to blame for a problem |

The other `UM2_*` variables are developer diagnostics and A/B switches; `grep getenv um2run.c um2bus.c um2aud.c`.

## Limits (alpha)
- Speed: the A9 is much slower than the cartridge's RP2350, so the picture is drawn at a lower frame rate than on a real cartridge. Measured on a DE10-Nano (28 Oct 2026): Pac-Man about 26 frames/s (game speed right), BattleZone about 23, Star Wars about 40, Veccy Road about 39; Punch-Out manages only about 38 of the 60 frames/s it wants, so it plays at about two thirds speed and its speech sounds slow. The OSD is laggy while a game runs.
- Start-up: about 1 to 2 seconds of static at the start (cart audio while both guest cores still
  share one CPU), and a LOADING screen for 10 to 20 seconds on the big images.
- Picture: slanted text and occasional jitter; the left edge is clipped in the cartridge menus; landscape games are cropped on the portrait screen.
- Only images built with the public UVMC2 SDK runtime are known to work. Other firmware, or other versions, may need model work: run without `--bus` for a census of what is not handled.
- Needs both ARM cores: it refuses to start with one CPU online.
